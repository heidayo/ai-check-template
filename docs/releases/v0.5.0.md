# v0.5.0 Release Notes

Release date: 2026-07-03
Release state: Released
Package: `ai-check-template@0.5.0`
Dist-tag: `latest`

v0.5.0 is the npm CLI release for the repository-current upgrades from SPEC-0056 through SPEC-0065.

> **Publish status**: Published to npm as `ai-check-template@0.5.0` (dist-tag `latest`) on 2026-07-04. The `git tag v0.5.0` and the GitHub Release are in place, and the release is promoted to Latest.

## Highlights

- **3-way update (SPEC-0056)**: `update` now compares each managed file against the baseline hash recorded in the install state, and by default keeps user-modified managed files as `skip-modified` instead of overwriting them. `--force-managed` overwrites after writing a `<file>.bak-<version>` backup, `--keep-local` makes the default explicit, and `--diff` prints a read-only unified diff. The install state auto-migrates to schema v2. **Breaking behavior change**: the previous always-overwrite update is replaced by modified-file protection.
- **Local overlay (SPEC-0057)**: each distributed `scripts/ai-check*.sh` sources `scripts/ai-check.local.sh` when present, and `.claude/rules/local/` holds project rules. Both are installer-untouched, so you can customize without editing managed files.
- **`.ai-check.yaml` step config (SPEC-0058)**: `run` can read a `.ai-check.yaml` (or `.ai-check.json`) that replaces, re-commands, or disables the gate steps per gate. It is opt-in — without the file, `run` keeps the current package-script behavior.
- **`report` command + run-result schema (SPEC-0059)**: `report` matches an expect file's AC / Test Matrix against a `run --json` result and prints the verification status of your declared criteria as text, markdown, or json. `--strict` exits non-zero on any UNVERIFIED or FAIL. The `run --json` output is now fixed by `run-result.schema.json`.
- **Profile composition rules (SPEC-0060)**: the base+addon composition rules are specified and snapshot-locked, and a script-key collision between profiles now fails fast instead of silently overwriting.
- **Monorepo / workspace (SPEC-0061)**: `--workspace <pkg-dir>` points `init` / `update` / `doctor` at one workspace package in a monorepo, rendering each gate step as a package-manager-specific workspace invocation (`pnpm --filter`, `npm run --workspace`, and so on).
- **CI monorepo + SARIF (SPEC-0062)**: the CI templates add commented paths-filter / matrix examples, an opt-in Semgrep SARIF upload to GitHub Code Scanning, and action SHA-pinning guidance.
- **RLS template parameterization (SPEC-0063)**: the `supabase-rls` RLS test templates are now schema-agnostic — SQL uses psql `\set` with `format('%I', :'var')` and TypeScript uses env fallbacks — so they no longer hardcode a schema.
- **authz Semgrep rules (SPEC-0064)**: the `supabase-rls` addon ships example Semgrep rules that flag ignored authz / RLS checks. They are opt-in via an added `--config`; the default `security:sast` gate is unchanged.
- **Custom profiles (SPEC-0065)**: `--profile-file <path>` defines a custom base profile from your own definition file, added additively. The four built-in base profiles and the `supabase-rls` addon remain completely unchanged.

## Limitations

- 3-way update changes the default behavior: locally modified managed files are kept as `skip-modified` and are only overwritten with `--force-managed` (which writes a `<file>.bak-<version>` backup first). Pin `@0.4.0` for the previous always-overwrite behavior.
- Custom profiles in v1 provide exactly one custom base profile per project; custom addons, multiple custom profiles at once, and composing a custom base with `+supabase-rls` are out of scope.
- The SARIF upload and the authz Semgrep rules are opt-in and are not wired into the default gate; target projects enable them explicitly.
- Custom profiles cannot be combined with `--workspace` in this release.
- The RLS templates are manual-copy: existing copies in target projects do not auto-follow future template changes.
