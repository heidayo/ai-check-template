## 背景・目的

`ai-check-template@0.2.0-alpha.0` は npm registry に publish 済みで、roadmap の v0.2.0 alpha scope はすべて完了した。次の作業は stable `v0.2.0` release のために repository state を整えることである。

本 SPEC では、`package.json` version を `0.2.0` に更新し、stable publish dry-run / docs / release notes / validation を `latest` dist-tag 前提に揃える。actual npm publish、Git tag、GitHub Release は不可逆な release operation のため、本 PR merge 後に maintainer 明示確認のもとで実行する。

## スコープ（含む）

- `package.json` version を `0.2.0` に更新する
- CLI install state test expectation を `0.2.0` に更新する
- `make validate` の package version / stable publish dry-run preflight を更新する
- README / README-ja / CLI docs / roadmap を stable release prep 状態に更新する
- `docs/releases/v0.2.0.md` を追加し、stable release candidate の内容と publish 手順を記録する
- SAGE SPEC / PLAN / TASK を 6 軸 100/S++ で採点し、検証結果を記録する

## スコープ外（明示的に除外）

- actual `npm publish`
- npm dist-tag mutation
- Git tag / GitHub Release 作成
- package runtime behavior の変更
- `src/**` の変更
- `package-templates/**` の変更
- `.github/**` の変更
- `sage/**`, `.sage/**`, `templates/**`, `CLAUDE.md`, `.claude/**` の変更

## CLAUDE.md / .claude/rules 連携

本 SPEC では repository の `CLAUDE.md` / `.claude/**` を変更しない。実装エージェントは AGENTS.md の standard lane / File Scope / TASK-ID commit hook を守る。追加で守る具体ルールは「publish prep と actual publish を混同しない」「registry write を行わない」「runtime code を変更しない」の 3 点である。

## Forbidden Shortcuts

- SPEC / PLAN / TASK 採点なしに実装へ進む
- File Scope 外の変更
- actual `npm publish` や dist-tag mutation を実行する
- `v0.2.0` tag / GitHub Release を作成する
- runtime behavior を変更する
- `--no-verify`, `--force`, `rm -rf`
- npm auth token / OTP / auth URL / personal email を docs に書く

## 要件

### 機能要件

- [FR-01] `package.json` は `0.2.0` を示す
- [FR-02] install state test は package version `0.2.0` を期待する
- [FR-03] `make validate` は stable publish preflight として `npm publish --dry-run --tag latest --json` を実行する
- [FR-04] README / README-ja / `docs/cli.md` は stable CLI path として `npx -y ai-check-template init` を示す
- [FR-05] `docs/releases/v0.2.0.md` は stable release candidate の contents / verification / post-merge publish steps を記録する

### 非機能要件

- [NFR-01] docs は alpha release note への履歴リンクを残す
- [NFR-02] docs は manual template path を残す
- [NFR-03] validation は dependency install なしで pass する

### セキュリティ要件

- [SEC-01] npm token / auth URL / OTP / personal email を docs に書かない
- [SEC-02] actual registry write を行わない
- [SEC-03] local absolute temp path を release notes に書かない

### 運用要件

- [OPS-01] PR は stable release prep のみに限定する
- [OPS-02] actual npm publish / tag / GitHub Release は PR merge 後に maintainer 明示確認で行う
- [OPS-03] publish 後に registry / `npx` smoke / GitHub Release を follow-up で確認する
