## 背景・目的

SPEC-0036 で hosted reusable workflow と Composite Action の foundation が main に入った。外部リポジトリが `@v0.3.0` で安定参照できるように、v0.3.0 の release notes、public docs、validation guard を整えたうえで、PR merge 後に `v0.3.0` tag と GitHub Release を作成する。

本 SPEC は GitHub Actions integration foundation の公開 release operation であり、npm package release ではない。

## スコープ（含む）

- `docs/releases/v0.3.0.md` を追加する
- README / README-ja / roadmap / GitHub Actions guide を v0.3.0 Released 状態に更新する
- `package-templates/ci-examples/README.md` の v0.3.0 foundation wording を release wording に更新する
- `Makefile` structural validation に v0.3.0 release docs / guide の guard を追加する
- PR merge 後に `v0.3.0` annotated tag と GitHub Release を作成する
- SAGE SPEC / PLAN / TASK を 6 軸 100/S++ で採点し、検証結果を記録する

## スコープ外（明示的に除外）

- npm package version bump / npm publish / dist-tag mutation
- `v1` major alias tag 作成
- GitHub Marketplace listing
- hosted workflow / Composite Action runtime behavior の変更
- `package.json`, `src/**`, `bin/**`, `.github/workflows/*.yml`, `ai-quality/action.yml` の変更
- `package-templates/**` の template content 変更（`package-templates/ci-examples/README.md` の docs 更新のみ許可）
- `sage/**`, `.sage/**`, `templates/**`, `CLAUDE.md`, `.claude/**` の変更

## CLAUDE.md / .claude/rules 連携

本 SPEC では repository の `CLAUDE.md` / `.claude/**` を変更しない。実装エージェントは AGENTS.md の standard lane / File Scope / TASK-ID commit hook を守る。追加で守る具体ルールは「v0.3.0 は GitHub Actions release であり npm release ではない」「Marketplace / `@v1` を完了済みと書かない」「tag / release は PR merge 後の main で作成する」の 3 点である。

## Forbidden Shortcuts

- SPEC / PLAN / TASK 採点なしに docs 更新へ進む
- File Scope 外の変更
- npm publish / npm dist-tag mutation を行う
- PR merge 前に `v0.3.0` tag を作る
- GitHub Marketplace listing や `@v1` alias を作る
- secret / token / private URL / auth URL を docs に書く
- `--no-verify`, `--force`, `rm -rf`

## 要件

### 機能要件

- [FR-01] `docs/releases/v0.3.0.md` は GitHub Actions foundation release notes として Highlights / Install / Verification / Limitations / Next を持つ
- [FR-02] README / README-ja / roadmap は v0.3.0 を Released として示し、`docs/releases/v0.3.0.md` と `docs/github-actions.md` にリンクする
- [FR-03] `docs/github-actions.md` は `@v0.3.0` exact pin が利用可能な release tag であると説明する
- [FR-04] `Makefile` は v0.3.0 release docs / guide の最低限を検証する
- [FR-05] PR merge 後に `v0.3.0` annotated tag と normal GitHub Release が存在する

### 非機能要件

- [NFR-01] docs は npm package が `0.2.0` のままであることを明記する
- [NFR-02] docs は Marketplace listing と future `@v1` alias を planned として扱う
- [NFR-03] validation は dependency install なしで pass する

### セキュリティ要件

- [SEC-01] docs に secret / token / auth URL / private URL を含めない
- [SEC-02] GitHub Release notes に npm auth material を含めない
- [SEC-03] no registry write operation

### 運用要件

- [OPS-01] release tag は PR merge 後、clean `main` で作成する
- [OPS-02] GitHub Release は draft でも prerelease でもない normal release とする
- [OPS-03] release operation 後に `gh release view v0.3.0` で状態を確認する

## Knowledge Management

| シナリオ | 記録先 | 責任者 |
|---|---|---|
| release docs と tag state の乖離 | `sage/failures.md` | maintainer |
| npm release と GitHub Actions release の混同 | `sage/anti-patterns.md` 昇格候補 | maintainer |
| GitHub Release operation failure | `sage/failures.md` | maintainer |

### failures / anti-patterns 更新フロー

1. 検出: docs grep、PR CI、`gh release view`、tag verification のいずれかで release state regression を確認する。
2. 記録: maintainer が command, expected output, actual output, affected doc/tag/release を `sage/failures.md` に記録する。
3. 昇格: npm release と GitHub Actions release の混同が 3 回累積した場合、follow-up SPEC または `sage/anti-patterns.md` への昇格候補として記録する。

## 契約

- API: なし

- リスク3: tag が feature branch commit を指す → PR merge 後の clean `main` で tag を作成
