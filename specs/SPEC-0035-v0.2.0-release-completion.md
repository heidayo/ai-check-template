## 背景・目的

`ai-check-template@0.2.0` は npm registry に publish 済みで、`latest` dist-tag は `0.2.0` を指している。`v0.2.0` annotated tag と GitHub Release も作成済みで、fresh npm cache の `npx -y ai-check-template@latest` smoke も pass した。

一方、repository docs にはまだ stable release prep / actual publish 前提の表現が残っている。本 SPEC では v0.2.0 を Released 状態として公開 docs / release notes / validation guard に反映し、v0.3.0 着手前の release completion を閉じる。

## スコープ（含む）

- README / README-ja の v0.2.0 status を Released に更新する
- `docs/cli.md` を published stable CLI 表現に更新する
- `docs/roadmap.md` の v0.2.0 status と scope heading を Released に更新する
- `docs/releases/v0.2.0.md` を post-publish evidence 付きの release notes に更新する
- `package-templates/README.md` の status に v0.2.0 CLI release を追加する
- `Makefile` structural validation に v0.2.0 Released status check を追加する
- SAGE SPEC / PLAN / TASK を 6 軸 100/S++ で採点し、検証結果を記録する

## スコープ外（明示的に除外）

- package version bump
- package runtime behavior の変更
- npm registry への write operation
- npm dist-tag mutation
- Git tag / GitHub Release の新規作成または変更
- `src/**`, `bin/**`, `package-templates/**` 内の README 以外の変更
- `.github/**`, `sage/**`, `.sage/**`, `templates/**`, `CLAUDE.md`, `.claude/**` の変更

## CLAUDE.md / .claude/rules 連携

本 SPEC では repository の `CLAUDE.md` / `.claude/**` を変更しない。実装エージェントは AGENTS.md の standard lane / File Scope / TASK-ID commit hook を守る。追加で守る具体ルールは「release completion と future publish prep を混同しない」「registry write を行わない」「runtime code を変更しない」の 3 点である。

## Forbidden Shortcuts

- SPEC / PLAN / TASK 採点なしに docs 更新へ進む
- File Scope 外の変更
- npm registry write / dist-tag mutation を行う
- Git tag / GitHub Release を変更する
- npm auth token / auth URL / OTP / personal email を docs に書く
- `--no-verify`, `--force`, `rm -rf`

## 要件

### 機能要件

- [FR-01] README / README-ja / roadmap は v0.2.0 を Released として示す
- [FR-02] `docs/cli.md` は `ai-check-template@0.2.0` が published stable CLI であることを示す
- [FR-03] `docs/releases/v0.2.0.md` は npm registry / npx smoke / tag / GitHub Release evidence を記録する
- [FR-04] `package-templates/README.md` は v0.2.0 CLI release を status に含める
- [FR-05] `Makefile` は v0.2.0 Released status と release evidence の最低限を検証する

### 非機能要件

- [NFR-01] docs は alpha history へのリンクを残す
- [NFR-02] docs は manual template path を残す
- [NFR-03] validation は dependency install なしで pass する

### セキュリティ要件

- [SEC-01] npm token / auth URL / OTP / personal email を docs に書かない
- [SEC-02] smoke test temp path 等の local absolute path を docs に書かない
- [SEC-03] registry write operation は実行しない

### 運用要件

- [OPS-01] PR は release completion docs のみに限定する
- [OPS-02] CI failure は同一 branch で修正し、`make validate` と GitHub Actions 再実行で閉じる
- [OPS-03] v0.3.0 planning は本 SPEC merge 後に開始する
