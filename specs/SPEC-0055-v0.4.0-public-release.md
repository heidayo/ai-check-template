## 背景・目的

SPEC-0054 で `0.4.0` npm release candidate は validation 済みになった。npm login も完了したため、公開用 docs を `release-ready / publish pending` から `Released` に切り替え、merge 後の main から npm publish、`v0.4.0` tag、GitHub Release、post-publish smoke を実行する。

## 対象ユーザー

- npm `latest` から `run` / `expect` を利用する利用者
- release state を README / roadmap / release notes で確認する reviewer
- tag と GitHub Release を参照する外部導入者

## スコープ（含む）

- README / README-en / roadmap / CLI docs / package template status を v0.4.0 Released 状態に更新する
- `docs/releases/v0.4.0.md` を public release notes に更新する
- Makefile structure guards を Released wording に合わせる
- merge 後に npm publish / git tag / GitHub Release / smoke test を実行する

## スコープ外（明示的に除外）

- runtime CLI behavior の変更
- npm package version の再変更
- hosted GitHub Actions `v0.3.0` contract の変更
- npm token や auth secret の記録

## 要件

### 機能要件
- [FR-01] public docs は v0.4.0 を Released と表現する
- [FR-02] release notes は npm publish / tag / GitHub Release / smoke test の確認コマンドを含む
- [FR-03] Makefile は v0.4.0 Released wording を検証する

### 非機能要件
- [NFR-01] `make validate` は pass する
- [NFR-02] docs update は package contents に含まれる published docs として矛盾しない

### セキュリティ要件
- [SEC-01] npm auth token、GitHub token、OTP、session URL を repository に記録しない
- [SEC-02] publish は npm authenticated session で実行し、dry-run ではなく実 publish であることを確認する

### 運用要件
- [OPS-01] `npm publish --tag latest --access public` が成功する
- [OPS-02] `git tag v0.4.0` と `git push origin v0.4.0` が成功する
- [OPS-03] GitHub Release `v0.4.0` が作成される
- [OPS-04] `npx -y ai-check-template@latest --help` smoke が成功する

## 受け入れ条件（Acceptance Criteria）

- [x] AC-01: docs が `v0.4.0` を `Released` と表示する
- [x] AC-02: `make validate` が pass
- [x] AC-03: `npm view ai-check-template version dist-tags --json` で latest が `0.4.0`
- [x] AC-04: `git tag --list v0.4.0` が `v0.4.0` を返す
- [x] AC-05: `gh release view v0.4.0 --json tagName,isDraft,isPrerelease,url` が non-draft / non-prerelease を返す

## 異常系

- npm publish が失敗する場合: tag / GitHub Release を作成せず、auth / registry error を報告する
- tag push が失敗する場合: npm publish 済みであることを明記し、tag/release の再実行手順を残す
- smoke test が失敗する場合: publish 済み状態と failure output を分けて報告する

## 契約

- API: なし
- DB: なし
- イベント: なし
- Release contract: npm `latest` = `0.4.0`, git tag `v0.4.0`, GitHub Release `v0.4.0`

## リスク

- リスク1: docs を Released にした後 publish が失敗する → publish 前に `npm whoami` と `make validate` を確認し、失敗時は release docs を戻す
- リスク2: npm publish 後に tag/release が失敗する → npm state と git state を明示して再実行可能にする
- リスク3: secret がログや docs に残る → auth values は記録せず、only command status を記録する

## 実装メモ（Implementation Agent向け）

docs update は PR merge し、publish は merge commit の main から実行する。GitHub Release body は `docs/releases/v0.4.0.md` をそのまま使う。`npm login` の一時URLやtokenはdocs / commit message / PR bodyに含めない。
