## 背景・目的

v0.1.0 の OSS 化スコープは、README / governance / GitHub Actions / example / test design / initial dogfooding report まで完了した。最後に、公開 release notes を repository に残し、`v0.1.0` Git tag と GitHub Release を作成して manual template set を配布可能な milestone として閉じる。

## 対象ユーザー

- v0.1.0 を導入したい early adopter
- release 内容と制限事項を確認したい contributor
- v0.2.0 CLI scaffolding へ進む maintainer

## スコープ（含む）

- `docs/releases/v0.1.0.md` を作成する
- README / README-ja / roadmap に release notes への導線と v0.1.0 Released status を反映する
- `package-templates/README.md` の status を v0.1.0 released に更新する
- `Makefile` の structural validation に release notes の必須セクション検証を追加する
- PR merge 後、`v0.1.0` annotated tag を main merge commit に作成して push する
- GitHub Release `v0.1.0` を release notes file から作成する

## スコープ外（明示的に除外）

- npm package publish
- CLI scaffolding
- package template runtime behavior の変更
- `.github/workflows/**` の変更
- `sage/**`, `.sage/**`, `templates/**`, `CLAUDE.md`, `.claude/**` の変更
- external dogfooding graduation claim

## CLAUDE.md / .claude/rules 連携

本 SPEC では `CLAUDE.md` / `.claude/rules/**` を変更しない。release は repository docs と GitHub metadata の操作であり、Claude Code-specific files は触らない。

## Forbidden Shortcuts

- SPEC / PLAN / TASK 採点なしに release へ進む
- File Scope 外の変更
- `--no-verify`, `--force`, `rm -rf`
- npm publish を行う
- external dogfooding graduation を主張する
- release notes に secret / private URL / unfinished marker patterns を含める
- `v0.1.0` tag が既に存在する場合に上書きする

## 要件

### 機能要件

- [FR-01] release notes が v0.1.0 の deliverables / install / verification / limitations / next steps を含む
- [FR-02] README / README-ja / roadmap が release notes にリンクする
- [FR-03] roadmap が v0.1.0 を Released として示す
- [FR-04] `make validate` が release notes の必須構造を検証する
- [FR-05] PR merge 後、`v0.1.0` tag が main release commit を指す
- [FR-06] GitHub Release `v0.1.0` が release notes を本文として公開される

### 非機能要件

- [NFR-01] release notes は 80-240 行に収める
- [NFR-02] root CI は dependency install なしで pass する
- [NFR-03] release は normal release とし、draft / prerelease にはしない
- [NFR-04] カバレッジ閾値: N/A。代替指標として AC-01..AC-13 と GitHub Release verification を coverage gate とする

### セキュリティ要件

- [SEC-01] release notes に secret 直書きパターンを含めない
- [SEC-02] release notes に private URL pattern を含めない
- [SEC-03] release notes は npm package publish を示唆しない
- [SEC-04] tag が既に存在する場合は作成を停止する

### 運用要件

- [OPS-01] PR #9 CI pass 後に merge する
- [OPS-02] merge 後の main commit に annotated tag `v0.1.0` を作成する
- [OPS-03] GitHub Release 作成後、`gh release view v0.1.0` で公開状態を確認する

- 想定エラー3: release notes が npm publish 済みに読める → limitations に manual template release と明記する
- 境界ケース1: PR merge 後 main が進んだ → tag 前に `git pull --ff-only origin main` で release commit を確認する

## Knowledge Management

| シナリオ | 記録先 | 責任者 |
|---|---|---|
| release 手順が失敗する | `sage/failures.md` | maintainer |
| release notes と実配布物が乖離する | follow-up SPEC | maintainer |
| 同種の release gap が 3 回累積する | `sage/anti-patterns.md` 昇格候補 | maintainer |

### failures / anti-patterns 更新フロー

1. 検出: PR CI、tag push、GitHub Release 作成のいずれかで失敗を確認する。
2. 記録: maintainer が再現条件、コマンド、期待結果、実際の失敗を `sage/failures.md` に記録する。
3. 昇格: 同種の release procedure gap が 3 回累積した場合、`sage/anti-patterns.md` への昇格候補として記録する。
