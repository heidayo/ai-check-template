## 背景・目的

v0.2.0 で npm CLI scaffolding が stable release になった。roadmap の次段階は、GitHub Actions integration を「コピー用 example」から「外部リポジトリが `uses:` で参照できる hosted contract」へ引き上げること。

本 SPEC では v0.3.0 foundation として、hosted reusable workflow と Composite Action を repository root に追加し、導入 docs と validation guard を整備する。Marketplace listing や major alias tag は後続 release operation に分離する。

## スコープ（含む）

- hosted reusable workflow `.github/workflows/ai-quality.yml` を追加する
- Composite Action `ai-quality/action.yml` を追加する
- `docs/github-actions.md` を追加し、hosted reusable workflow / Composite Action / existing copy examples の使い分けを説明する
- README / README-ja / roadmap / package-templates CI examples README に v0.3.0 foundation への導線を追加する
- `Makefile` structural validation に hosted workflow / action / docs の guard を追加する
- SAGE SPEC / PLAN / TASK を 6 軸 100/S++ で採点し、検証結果を記録する

## スコープ外（明示的に除外）

- v0.3.0 tag / GitHub Release 作成
- `v1` major alias tag 作成
- GitHub Marketplace listing
- npm package version bump / publish
- CLI runtime behavior の変更
- `src/**`, `bin/**`, `package.json`, `package-templates/**` の template content 変更（`package-templates/ci-examples/README.md` の docs 更新のみ許可）
- existing template workflow YAML の変更
- `sage/**`, `.sage/**`, `templates/**`, `CLAUDE.md`, `.claude/**` の変更

## 要件

### 機能要件

- [FR-01] `.github/workflows/ai-quality.yml` は `workflow_call` で呼べる hosted reusable workflow である
- [FR-02] `ai-quality/action.yml` は Composite Action として `init` ではなく target project の既存 `ai:check` を実行する
- [FR-03] reusable workflow と action は `package-manager`, `node-version`, `working-directory`, `install-command`, `check-command`, `upload-ai-check-artifacts` を持つ
- [FR-04] docs は hosted reusable workflow、Composite Action、copy examples の使い分けを示す
- [FR-05] validation は YAML syntax と required structure を検証する

### 非機能要件

- [NFR-01] hosted workflow / action は Node-first project を対象にしつつ `pnpm`, `npm`, `yarn`, `bun` を扱う
- [NFR-02] docs は `@v0.3.0` exact pin と future `@v1` major alias の違いを明記する
- [NFR-03] Marketplace listing は planned とし、done と書かない

### セキュリティ要件

- [SEC-01] `permissions: contents: read` を workflow に明記する
- [SEC-02] docs / YAML / action に secret 直書きパターンを含めない
- [SEC-03] third-party actions は major pin 以上で固定する

### 運用要件

- [OPS-01] PR は v0.3.0 foundation のみに限定する
- [OPS-02] release operation は follow-up SPEC に分離する
- [OPS-03] `make validate` と GitHub Actions `validate` pass 後に merge する
