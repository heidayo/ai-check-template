## 実装方針

### 採用案

1. Release notes を Markdown file として repo に残す
2. PR #9 で docs readiness を merge する
3. CI pass / merge 後の `origin/main` に annotated tag `v0.1.0` を作る
4. GitHub Release body は `docs/releases/v0.1.0.md` をそのまま使う

### 不採用案

- npm publish: v0.2.0 以降の scope
- auto-generated release notes only: limitations / manual install / dogfooding caveat を明示したい
- direct tag before PR merge: release notes が tag に含まれない
